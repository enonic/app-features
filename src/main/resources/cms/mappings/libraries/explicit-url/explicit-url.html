Fixed setup and how to edit the tests

Cases live in /lib/explicit-url-tests.ts. Execution context is com.enonic.cms.features, branch draft; individual calls may select master. Both target pages must exist on both branches.

A configured site base URL is used only when base explicitly identifies that site in the selected project and branch. When the explicit base has no configured base URL, the expected path is relative to that base: /features/subsite/pageurl with base /features/subsite produces /pageurl. Without base, the expected URL is the full content path, such as /unbased/subsite/folder, without a project or branch prefix. The target content does not implicitly select a site base URL. A target outside the explicit base's subtree is expected to throw the specified exception. Returning a URL or null fails that case.

This baseline expects /features to have base URL https://example.com/demo on both branches, and /features/subsite to have https://subsite.com on both branches. Changing content or configuration does not change the expected values.

The main-site and nested-site sections also cover /unbased/folder and /unbased/subsite/folder. Both sites have no assigned apps or configured base URL. Content outside a site is covered by /libraries/explicit-url, including selection of its parent folder /libraries as an explicit base. These targets must exist on both branches.

Calls temporarily use the Java PortalUrlService.pageUrl API because the JS wrapper does not expose base. Query spaces encoded as + or %20 are treated as equivalent.
